# หน่วยสืบสวนฐานข้อมูล (SQL Detective)

เกมไขคดีด้วยการเขียน SQL — รัน SQLite จริงในเบราว์เซอร์ผ่าน [sql.js](https://sql.js.org/)
ไม่มี backend ไม่มี API ทุกอย่างอยู่ฝั่ง client

## เริ่มใช้งาน

```bash
npm install     # postinstall จะคัดลอก sql-wasm.wasm ไปที่ public/ ให้อัตโนมัติ
npm run dev     # http://localhost:3000
```

Build:

```bash
npm run build && npm start
```

## หน้าเว็บ

| เส้นทาง | คืออะไร |

| `/`     | หน้า Home — ปุ่มเริ่มเกม, วิธีเล่น, รายการคดี, **คู่มือคำสั่ง SQL** 8 บท, ตารางในฐานข้อมูล |

## เล่นซ้ำได้ไม่ต้องจำคำตอบ

ทุกครั้งที่เปิด `/play` เกมจะ**สุ่มป้ายชื่อใหม่ทั้งเมือง** ผู้เล่นเลยต้องค้นฐานข้อมูลเองทุกรอบ
โครงข้อมูล ความสัมพันธ์ระหว่างตาราง และตรรกะของทุกคดี**เหมือนเดิมเป๊ะ** เปลี่ยนแค่ชื่อที่มองเห็น

| สุ่มอะไร | ที่มา | ใช้กับคดีที่ตอบเป็น |
|----------|-------|---------------------|
| ชื่อคน (`people.name`) | `NAME_POOL` ใน `seed.ts` | ชื่อคน (คดีส่วนใหญ่) |
| ชื่อสถานที่/เขต/สถานี/ร้าน | `places.ts` | สถานที่ (เช่น คดีที่ 2) |

ชื่อสถานที่**สุ่มเป็นโซน** ไม่ได้สุ่มทีละชื่อ — โซนหนึ่งได้คำนำหน้าหนึ่งคำ สถานที่ทุกแห่งในโซนจึงใช้คำเดียวกัน
(เขต `Amber Bay` คู่กับ `Amber Wall`, `Amber Station`, `Amber Hardware`) ถ้าสุ่มทีละชื่อ เมืองจะมั่วจนอ่านเบาะแสไม่รู้เรื่อง
คำต่อท้ายก็สุ่มด้วย (`Plaza` / `Square` / `Commons`) กันผู้เล่นจำแบบ "คำตอบคือที่ที่ลงท้ายว่า Plaza"

การแทนชื่อทำทีเดียวกับ SQL ทั้งก้อนและกับ `brief` / `hint` / `goal` / `solution` / `answers` ของทุกคดี
โดยเรียงกุญแจจากยาวไปสั้นแล้วแทนรอบเดียว (สำคัญ: `Old Town` เป็นส่วนหนึ่งของ `Old Town Wall`)

> **เพิ่มสถานที่ใหม่ใน `seed.ts` แล้วต้องไปต่อ slot ใน `places.ts` ด้วย** ไม่งั้นชื่อนั้นจะไม่ถูกสุ่ม
> และโจทย์อาจอ้างถึงสถานที่ที่ไม่มีอยู่จริงในรอบนั้น

## สมุดบันทึก

ปุ่ม **📓 สมุดบันทึก** มุมขวาล่างเปิดลิ้นชักที่เก็บโน้ตของผู้เล่น

- **เก็บคิวรีไว้ใช้ซ้ำ** — กด **📌 เก็บคิวรี** ใต้คอนโซล คิวรีที่เขียนค้างอยู่จะถูกเก็บลงสมุด
  แล้วกด **ใส่คอนโซล** จากโน้ตใบนั้นเพื่อวางกลับมาแก้ต่อได้ทุกเมื่อ
- **จดเบาะแสเอง** — พิมพ์อะไรก็ได้ในช่องบนสุด ถ้าขึ้นต้นด้วย `SELECT` หรือ `WITH`
  ระบบจะถือว่าเป็นคิวรีและติดปุ่ม *ใส่คอนโซล* ให้เอง
- โน้ตทุกใบติดป้ายว่าจดตอน**สำนวนไหน** และ**อยู่ข้ามคดี** — จดที่คดี 3 เปิดอ่านตอนคดี 12 ได้
- เก็บลง `localStorage` (คีย์ `sql-detective:notes:v1`) จึง**อยู่รอดตอนรีเฟรช**
  ข้อควรรู้: รีเฟรชแล้วชื่อคนในเกมจะสุ่มใหม่ โน้ตที่จดชื่อคนไว้จึงใช้อ้างอิงข้ามรอบไม่ได้ แต่โน้ตที่เป็นคิวรียังใช้ได้เสมอ

## เนื้อหาที่ฝึก

| คดี | หัวข้อ |
|-----|--------|
| 1 | `SELECT` · `WHERE` · `AND` |
| 2 | `ORDER BY` · `LIMIT` |
| 3 | `JOIN` สามตาราง |
| 4 | `GROUP BY` · `COUNT` |
| 5 | เปรียบเทียบวันเวลาแบบ TEXT |
| 6 | Subquery · `NOT IN` |
| 7 | `HAVING` (ต่างจาก `WHERE` ยังไง) |
| 8 | JOIN หลายตาราง + `BETWEEN` |
| 9 | `LEFT JOIN` + `IS NULL` (anti-join) |
| 10 | `strftime` ดึงชั่วโมง + `GROUP BY` |
| 11 | SELF JOIN + `julianday` คิดส่วนต่างเวลา |
| 12 | `COUNT(DISTINCT …)` + `HAVING` |
| 13 | Window function — ยอดสะสม `SUM() OVER (PARTITION BY … ORDER BY …)` |
| 14 | `LAG()` เทียบกับแถวก่อนหน้า |
| 15 | CTE หลายชั้น — รวมสามเงื่อนไขจากสามตาราง |
| 16 | `WITH RECURSIVE` ไล่สายขึ้นไปหาต้นทาง |

คดี 6–8 ต่อกันเป็นเนื้อเรื่องเดียว (คดีพ่นสีกำแพงเมืองเก่า) คนที่ดูเหมือนผิดในคดี 6 จริง ๆ แล้วโดนใส่ร้าย
ส่วนคดี 13–16 เป็นอีกเนื้อเรื่อง (ขบวนการเงินเทา) จบที่การไล่สายหาหัวหน้าด้วย recursive CTE

## ฐานข้อมูล

12 ตาราง ~480 แถว — `people` (44 คน 5 เขต), `complaints`, `vehicles`, `parking_tickets`,
`cctv_logs`, `hotel_stays`, `purchases`, `phone_calls`, และชุดที่ใช้ในคดี 9 เป็นต้นไป
`transit_cards`, `transit_taps`, `bank_transactions`, `crew_links`

ชื่อคนถูกสุ่มใหม่ทุกครั้งที่เริ่มเกม (ดู `pickSessionNames` ใน `seed.ts`) เงื่อนไขของทุกคดีอิงกับ `id`
ไม่ใช่ชื่อ — จำคำตอบจากรอบก่อนแล้วมาตอบซ้ำไม่ได้

## เพิ่มคดีเอง

1. เติมข้อมูล/ตารางใหม่ใน `src/data/seed.ts`
2. ต่อ object ใหม่ท้าย array ใน `src/data/cases.ts`

UI, schema panel และรายการคดีในหน้า Home ปรับตามอัตโนมัติ ไม่ต้องแก้คอมโพเนนต์

## เพิ่มบทในคู่มือ

ต่อ object ใหม่ท้าย array ใน `src/data/guide.ts` — สารบัญกับตัวนับหัวข้อในหน้า Home ปรับตามเอง
โครงหนึ่งบทคือ บท → หัวข้อ (`topics`) → ตัวอย่าง (`examples`) + `pitfalls`
ช่อง `explain` กับ `pitfalls` ใส่ HTML tag พื้นฐาน (`<b>`, `<code>`) ได้

## หมายเหตุ

- ความคืบหน้าเก็บใน state เท่านั้น รีเฟรชแล้วเริ่มใหม่ — ถ้าอยากให้จำ ค่อยต่อ `localStorage` ใน `useGame`
- คิวรีที่มี `INSERT/UPDATE/DELETE/DROP/ALTER` ถูกบล็อกใน `lib/sqlGuard.ts`
- ฟอนต์โหลดจาก Google Fonts ผ่าน `<link>` ใน `layout.tsx` — ถ้าต้องการออฟไลน์เต็มรูปแบบ ให้ย้ายไป `next/font/local`
